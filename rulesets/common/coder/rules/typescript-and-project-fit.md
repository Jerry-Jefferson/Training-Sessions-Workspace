# TypeScript And Project Fit

- Preserve strict typing and narrow unknown data at boundaries instead of spreading `any` or unchecked assertions.
- Inspect the project's naming, exports, module structure, error handling, styling, state, and testing patterns before adding code.
- Prefer the smallest local implementation that matches established conventions.
- Add a new abstraction only for demonstrated complexity or reuse.
- Do not add dependencies, change package managers, or rewrite configuration without an explicit decision.
